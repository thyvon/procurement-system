Tenancy: every approval table carries entity_id → entities (cascade) — drawn once, applies to all. Audit: created_by / updated_by → users (nullOnDelete) on all tables except the two history tables. user_id edges: current_assignee_id · acted_by · step assignees.user_id → users. Subject link: subject_type + subject_id, validated by ApprovalSubjectRegistry, never a FK.

2. Approval workflow

Five engine states, one transaction per call, row locked while decided. Config tables are only read by this flow — never written.

flowchart TD
    PRE["Preview
reads settings · flows · steps · toca (candidates)"]
    DRAFT["Save draft
upserts approval_drafts"]
    SUB["Submit — one DB transaction"]
    CHECK{"guards"}
    WR["deletes approval_drafts
inserts approval_requests (pending)
inserts approval_request_step_assignees"]
    PARK["record steps stamped
park on first decide step"]
    WAIT["pending — waits on assignees"]
    ACT{"Decision
approve / reject / return / cancel"}
    ADV["approve · co-signers left → stay on step"]
    NEXT["approve · step done → advance"]
    DONE["approved"]
    CLOSE["reject / return → all unacted rows stamped"]
    CANCEL["cancel (submitter only)"]
    EVN["ApprovalStatusChanged"]
    SUBJ["Listener updates the subject document"]

    PRE --> DRAFT --> SUB --> CHECK
    CHECK -->|"missing band / assignee / authority
or a round is already pending"| ERR["422 / 403 — nothing written"]
    CHECK -->|"ok"| WR --> PARK --> WAIT --> ACT
    ADV --> WAIT
    NEXT --> WAIT
    NEXT --> DONE
    ACT -->|"reject / return"| CLOSE --> EVN
    ACT -->|"cancel"| CANCEL --> EVN
    DONE --> EVN
    EVN --> SUBJ
Submit guards, in orderpolicy → one pending round per document → subject status must be draft/returned → active band covers the amount → every decide step has an assignee → each assignee passes TOCA.
Co-signingSeveral users per step: each approves on the same step; one reject/return closes the round for everyone and stamps all unacted rows.
Snapshot isolationConfig edits replace steps wholesale, but a round only reads its own snapshot — in-flight requests never change.
Authority is re-checkedTOCA covers amount + step key at submit and at every decision, against the frozen amount_snapshot.
